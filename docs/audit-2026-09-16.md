# Jackdaw mobile audit (2026-09-16, v1.12.0+20)

A fresh read of `lib/`, done the day the first TestFlight build went out. It
follows the shape of the web client's audit (closed at 9.0 on 2026-09-15 in
the `jackdaw` repo): a score per dimension, findings ranked by severity, and a
worklist. It is a read, not a fix pass. Nothing in the tree was changed.

**How it was measured.** Three parallel code reviews (chat; the knowledge
screens; auth, settings and the inner workings), each with `file:line` for
every claim; a live walk through every screen on an iOS 26 simulator signed
in to a real brain; `fvm flutter analyze` (clean) and `fvm flutter test`
(154/154); and a contract check of every `/api/*` path the app calls against
the current Mantle server tree (41/41 exist). Screenshots were taken of every
route. What could not be checked: Android, a real device (push, alarms), the
software keyboard (the simulator uses the Mac's), and anything under load.

| Dimension             | Score | Why                                                                                                                 |
| --------------------- | ----- | ------------------------------------------------------------------------------------------------------------------- |
| Standards conformance | 6.0   | No Material, no `Scaffold`, tokens nearly everywhere. But 17 `fontSize:` literals, 3 hardcoded colours, unpaired fills, five date formatters, four copies of the delete sheet. |
| Correctness           | 5.5   | Eleven confirmed bugs, two of them user-visible on first use (Journal order, Journal composer under the keyboard).  |
| Performance           | 7.0   | Not measured. Streaming is frame-batched and paged; two known jank sources (image placeholder resize, `loadMore` snapshot). |
| Security posture      | 5.0   | Token in Keychain, no logging, E2E push. But the Android direct-push path copies the bearer into plain storage, logout leaves five things behind, and deep links have no allowlist. |

## What works

- **Auth gate** is one source of truth: session state drives the router
  redirect; a 401 clears the token and bounces to login. Bearer lives only in
  the platform keychain. Nothing logs.
- **The API contract is intact.** All 41 paths the app calls exist on the
  server, including the split-aware probe that recovers the brain address from
  an owner-app URL.
- **Chat streaming** is careful: stale-turn events dropped by id, round reset,
  `Last-Event-ID` resume, capped backoff, lifecycle pause, idempotent offline
  replay with poison-row drop.
- **Markdown** is token-driven end to end, including syntax highlighting from
  the theme's chart ramp; bad TeX falls back to source instead of crashing.
- **Push** enrolment never sends the Mantle bearer to the relay; decrypt
  failure shows a generic body, never a crash.
- **Every screen** has the guide's loading, empty and error states; light and
  dark both render correctly; all 43 themes are selectable.
- **Search, Notes, Files and Events** are genuinely usable on the phone today.

## Findings

Severity is ordered within each section. CONFIRMED = traced in code or seen
on the simulator; PLAUSIBLE = a reading that still wants a measurement.

### Security

1. **CONFIRMED · Bearer token copied to plain storage.** The Android direct
   push service writes the token with `FlutterForegroundTask.saveData`
   (SharedPreferences, not Keystore) at `lib/data/push/direct_push_service.dart:39-40`.
   It is never deleted: logout and 401 only stop the service, and
   `autoRunOnBoot: true` replays it after a reboot. Breaks the repo's own rule
   that secrets live only in secure storage.
2. **CONFIRMED · Logout is incomplete.** `AuthRepository.logout` revokes and
   clears the token and nothing else (`lib/data/auth/auth_repository.dart:28-31`).
   Left behind: the message cache and the offline outbox (no wipe method on
   `AppDatabase`; queued turns flush under the next login), the push
   subscription and device keypair (the device keeps decrypting the old
   account's pushes), scheduled event alarms, the direct-push service and its
   stored token, and the keepAlive agent cache. Sign out has no confirm and no
   error handling.
3. **CONFIRMED · Deep links have no allowlist.** A push payload's route is
   passed verbatim to `go()` (`lib/data/push/local_notifications.dart:48-52`,
   `lib/main.dart:73`); the router has no `errorBuilder`. On iOS the
   notification extension does not strip a `deepLink` already present in the
   raw APNs payload on its failure branch, so the relay could steer the app to
   any in-app route (bounded by the auth gate).
4. **CONFIRMED · Server URL is not validated.** `normalizeBaseUrl` only trims
   (`lib/data/server/server_config.dart:32-38`): `http://` is accepted, the
   probe follows redirects while the app client does not, so an http address
   that 301s passes the probe and then fails every authed request after sending
   the bearer in clear once.
5. **CONFIRMED · The 3xx logout check is a substring match.** Any redirect
   whose `Location` contains `/login` logs the user out
   (`lib/core/network/dio_provider.dart:47`); the SSE stream and direct-push
   service only stop on 401, so a revoked token keeps them reconnecting
   forever.
6. No certificate pinning or custom trust; platform trust only. Acceptable for
   self-hosted, but unstated.

### Correctness (confirmed unless marked)

Chat

1. **Concurrent sends.** `_send()` has no in-flight guard and the field stays
   enabled (`lib/features/chat/chat_composer.dart:180-193, 356`). A second
   keyboard send mid-turn replaces the active turn; the first turn's reconcile
   then wipes the second's live view (`chat_controller.dart:549-554, 633-635, 812`).
2. **`loadMore` overwrites live state with a stale snapshot**
   (`chat_controller.dart:449, 466-477`): tokens that streamed during the fetch
   vanish and the reply snaps back.
3. **Stop is ignored before the POST** (`chat_controller.dart:522-554,
   847-851`): a stop tapped during the location read or outbox flush does
   nothing and the turn still sends.
4. **Voice turns lock the composer** for the whole reply; "Transcribing…" shows
   until the assistant finishes and there is no Stop (`chat_composer.dart:261-274`).
5. `send()` writes state without a mounted check on the legacy-200 and catch
   paths (`chat_controller.dart:582-616`); server `warnings` are parsed and
   dropped (`chat_api.dart:182-183`); `loadMore` failures are silent and retry
   on every scroll tick (`chat_controller.dart:478-481`, `chat_screen.dart:59-65`).
6. PLAUSIBLE: inbox reloads race per SSE event (no sequencing); the open thread
   is only marked read once on open; the long-press copy menu likely loses the
   gesture arena to selectable markdown; `before: DateTime.now()` from the
   device clock can hide the newest rows.

Knowledge screens

7. **Journal composer hides under the keyboard.** Bottom padding is
   `viewPadding` when the keyboard is closed and **0** when it is open
   (`lib/features/journal/journal_screen.dart:346-354`); there is no `Scaffold`
   to resize the body. The chat composer does this correctly
   (`chat_composer.dart:308-310`).
8. **Journal is not in date order.** The list shows each entry's own date but
   never sorts by it (`journal_controller.dart:16` takes server order). Seen on
   the simulator: 06-09, 06-06, 06-11, 06-06.
9. **State written after dispose.** Riverpod 3 throws on `state =` after an
   autoDispose notifier is gone. Tasks, Journal, Events, Pages, Pending,
   Dashboard, Location, Push, Push-prefs, Reminder-channel, Theme controllers
   all write after an `await` with no `ref.mounted` guard (0 uses in 17 of 22
   controllers). Tap refresh, then back before the response: uncaught
   exception. Notes, Files, Search and Chat guard correctly.
10. **Home pending badge never refreshes.** Nothing invalidates the dashboard
    provider after approve/reject (`home_screen.dart:24, 135, 282`).
11. **Notes infinite scroll skips one row per delete.** Page-number paging plus
    optimistic local removal shifts the server boundary (`notes_api.dart:18-27`,
    `notes_controller.dart:149-159`).
12. **A failed image is cached as a failure forever.** `fileBytesProvider` is
    keepAlive and maps every error to `null` (`chat_api.dart:439-451`); the
    image screen has no retry.
13. Pages refresh drops the active search (`pages_controller.dart:32-35`);
    Tasks quick-add prepends above overdue rows (`tasks_controller.dart:51`);
    PLAUSIBLE: Pages search has no sequence guard; alarm sync covers only the
    first 50 upcoming events and runs unguarded from five call sites;
    `RandomThemeScheduler` can orphan a timer across lifecycle rebuilds.

Everywhere

14. Delete, approve, toggle failures are silent on every screen: the row just
    reappears (`_reloadSilently` only, no message).

### Consistency

- **Two header title treatments.** Sub-screens use a hardcoded 20/w600
  `TextStyle` (`lib/widgets/mantle_header.dart:72-76`); the chat header uses the
  script wordmark face at 24 for the agent name (`chat_screen.dart:287-291`).
- **Text under the 15pt floor, hardcoded:** 17 `fontSize:` literals across
  chat, conversations, home, pages, header. Badges 11–12, trail stamps 11,
  attachment meta 11, avatar initials ~11.
- **Hardcoded colours:** health green/amber on Home (`home_screen.dart:12-13`,
  with an apology comment) and white initials on an HSL fill in
  `agent_avatar.dart:36, 46`.
- **Unpaired fills:** offline-banner Retry (`primary` text on `secondary`);
  inline code (`secondary` fill, `foreground` text); `:::columns` panels
  (`muted` on the `muted` bubble, so invisible); reminder chips (`muted` fill,
  `foreground` text) while Notes and Search chips use the `secondary` pair;
  every settings row puts `mutedForeground` icons on a `card` fill.
- **Five date formatters** for one concept (Notes/Search, Pending, Journal,
  Events, Tasks), with different capitalisation and fallbacks. Chat shows no
  timestamps at all.
- **Three "add" patterns:** header `+` (Events), inline top field with `+`
  (Notes, Tasks), bottom composer with a check (Journal).
- **Delete is one ghost tap in a sheet**, copy-pasted four times, with no
  Cancel; Pending Reject is one tap; the only real confirm dialog is push
  Reset. Sign out has none.
- **Error state deviates** on Search and the image screen (text, no Retry).
- **Refresh blanks the list** on Inbox and Chat (`AsyncLoading` flash) although
  a silent reload exists. Home has no refresh at all; pull-to-refresh exists
  nowhere in the app.
- Header icons 18 vs 20 on the same bar; empty states with an icon on two
  screens only; off-scale spacing (2, 6, 10, 14) throughout; Files header shows
  the folder slug, and "1 folders".
- Stale copy: the composer placeholder reads "Message Mantle…"
  (`chat_composer.dart:351`); the direct-push channel is still `mantle_direct`.
- Settings says "Account & profile settings coming soon."
- The bright orange focus ring is the Jackdaw theme's own `ring`
  (`lib/theme/jackdaw_theme.dart:44`), so it is a choice, not a slip. It reads
  off-brand on the search field.

### What the web app has that the phone does not

The app's stated scope is chat, capture and read. Measured against that scope,
the gaps that matter most are marked ★.

**Scope rule (Jason, 2026-09-16):** do not build full edit mode for Pages or
other complicated screens; nobody edits a document that far on a phone.
Notes is the exception: capture and light editing belong there. Some things
make no sense to create on mobile at all, formulas and recall among them; when
the parity work reaches those, decide the approach first rather than porting
the web screen. So "Pages create/edit" below is a gap on paper, not a plan.

| Area           | On the phone                                   | Missing                                                                                                    |
| -------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Chat           | Thread per agent, stream, voice, attachments, offline queue | ★ Timestamps and date grouping; scroll-to-bottom; unread divider; image full-screen; share; delete thread; cancel a queued message; agent switch from the thread; haptics |
| Pages          | Tree, search, read, backlinks                  | Note backlinks not tappable; open in web. Create/edit/delete: **out of scope** by the rule above          |
| Notes          | Quick-add, tags, paging, edit, delete          | Text search (the API accepts `query`, nothing calls it); delete from the note view; digest toggle         |
| Tasks          | Quick-add, done toggle, delete                 | ★ Due date, priority, body, tags, comments, board columns; edit; detail; only the first 50                 |
| Journal        | Read, capture (text and voice)                 | ★ Edit, delete; mood, category, entry date, tags; the assistant's `gap` questions render as plain entries; paging |
| Events         | List, add, done, delete, device alarms         | ★ Edit; end time, recurrence, body; a real time picker (free-text HH:MM today); detail                    |
| Files          | Browse, image preview, upload                  | Rename, move, copy, download, folder create/delete, indexing toggle; non-image preview is a metadata sheet |
| Search         | Hybrid search, type chips, deep links          | Task/event/journal hits open the list, not the item; no load-more                                          |
| Pending        | Approve / reject                               | Question and form rendering; history; full args (truncated to 4 keys); agent name                          |

| Settings       | Theme, push, reminder channel, location        | ★ Which server and account you are signed in to; change server; app and server version; clear cache; biometric lock; per-agent notification prefs; password-manager autofill on login |
| Not on mobile  |                                                | Contacts, Tables, Draw, Apps, Email inbox, Recall, Heartbeats, Runs, Secrets, Models, Formulas, Team spaces, generic node view, all server settings |

### Layout and accessibility

- **Under 44pt:** composer attach/mic (~38), attachment clear (~28), audio play
  (36), done toggles (34×24), pages chevron (27), tag chips (~28), reminder
  chips (~32), backlink rows (~35), failed-message Retry (text only). Every
  `ShadButton` is the 40pt default; no `lg` size anywhere.
- **Overflow:** the note edit sheet is an unscrollable `Column` with a 6–12 line
  field plus keyboard inset; search and file sheets render summaries with no
  `maxLines`; the Events time column is a fixed 56pt bold cell.
- **Keyboard:** Journal (bug 7); Notes, Tasks and Search lists have no bottom
  inset or dismiss-on-scroll, so the tail sits under the keyboard.
- **Safe areas:** rows placed between the header and the body `SafeArea` get no
  side insets in landscape (Pages search, quick-add rows, Search chips, Files
  breadcrumb and upload row).
- **Landscape:** bubbles use 78% of the raw screen width, not the safe width;
  the two-row composer is ~110pt before the keyboard.
- **Permission prompt with no rationale:** opening Events for the first time
  fires the OS notification prompt cold.
- Icon-only buttons (header actions, upload row, composer) carry no semantic
  label.

### Tests and CI

- **No CI.** `.github/workflows` does not exist. Nothing gates a push; analyze
  and test run only when someone remembers.
- Covered: session states, login/logout, server probe, settings persistence,
  push controllers, offline queue and poison rows, chat paging and streaming,
  SSE parsers, markdown widgets.
- Not covered: the Dio auth interceptor (the most security-relevant path); any
  screen as a widget; deep links; `EventAlarms.sync`; flush-on-resume and
  cross-agent stuck rows; logout completeness; `PushDecryptor`; location; the
  theme controllers; the whole direct-push handler.

## Worklist, in order

1. **Security trio (one session):** move the direct-push token to secure
   storage and delete it on stop; make logout wipe cache, outbox, push keys,
   alarms and the service, with a confirm; allowlist deep-link routes and add a
   router `errorBuilder`; require `https` (allow `http` only for
   `localhost`/private ranges behind a visible warning); make the 3xx check a
   path match.
2. **CI gate:** a workflow that runs `fvm flutter analyze`, `fvm flutter test`
   and both no-codesign release builds on every push. The web audit's lesson
   holds here: every standard that survived was one a gate enforced.
3. **Mounted guards everywhere** (17 controllers), then a lint that keeps it
   that way. Add the missing `ref.mounted` in `send()`.
4. **The four first-use bugs:** Journal composer inset, Journal sort by
   `displayDate`, concurrent-send guard, `loadMore` merge instead of snapshot.
5. **One header title style, one date formatter, one delete confirm
   (`ShadDialog.alert`), one add pattern.** Delete the four sheet copies.
6. **Text floor and colours:** replace the 17 `fontSize:` literals with scale
   entries (add a `caption` entry to the scale if 11–12pt is truly wanted, and
   say so in the guide); replace the three hardcoded colours with status
   tokens; fix the five unpaired fills.
7. **Chat timestamps and date grouping**, scroll-to-bottom, image full-screen
   via the existing route, "Message <agent>…" placeholder.
8. **Settings identity:** server, account, app version, server version; change
   server; clear cache.
9. **Tap targets** to 44pt (a theme-level `ShadButton` size, padding on the
   small toggles), semantic labels on icon buttons, keyboard insets on the
   three lists, a rationale screen before the notification prompt.
10. **Parity that fits the phone's scope (★ rows):** Tasks due date and
    priority, Events edit and time picker, Journal edit/delete and `gap`
    answers. Not Pages editing (scope rule); formulas, recall, tables and
    drawing need a decision before any work.
11. **Tests for the gaps above**, starting with the interceptor, deep links and
    logout.
